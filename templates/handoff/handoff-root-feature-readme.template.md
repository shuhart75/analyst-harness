# Общий пакет функциональности `<package-id>`

Этот каталог является общей рабочей точкой аналитиков, разработчиков и тестировщиков. На машине разработчика достаточно клона `coda` и ссылки на этот каталог.

## Что делает SDD

1. Читает `handoff.json` и выполняет только `next_sdd_action` для входной редакции требований.
2. Берёт пакет из `next_sdd_action.package_path`.
3. После начала работы выполняет `claim`.
4. Формирует техническую декомпозицию в `returns/development-tasks/`.
5. После решения разработчиков выполняет `confirm-decomposition`. Подтверждённый снимок сразу доступен аналитику, но разработка его ответа не ждёт.
6. Сохраняет квитанции реализации по карточкам в `returns/implementation-results/`.
7. Тестировщик берёт исходные срезы и сохраняет квитанции в `returns/test-results/`.

## Независимые состояния

- Входная редакция управляет только актуальностью требований.
- Карточка хранит только состояние технической декомпозиции.
- Выполнение задачи фиксируется квитанцией реализации.
- Проверка фиксируется квитанцией среза.
- Фоновая передача аналитику не разрешает и не запрещает разработку.
