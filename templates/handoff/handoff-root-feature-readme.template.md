# Общий пакет функциональности `<package-id>`

Этот каталог является общей рабочей точкой аналитиков, разработчиков и тестировщиков. На машине разработчика достаточно клона `coda` и ссылки на этот каталог.

## Что делает SDD

1. Читает `handoff.json` и выполняет только `next_sdd_action` для входной редакции требований.
2. Берёт пакет из `next_sdd_action.package_path`, читает его `request.md`, `manifest.json` и инструкции.
3. После начала работы выполняет `claim`.
4. Выбирает один контур, читает только связанные требования и срезы, затем локальную SDD, найденные модули кода и соседние проверки. Весь `coda` и оба контура одновременно не загружает.
5. Формирует техническую декомпозицию в `returns/development-tasks/`; каждая карточка содержит постоянный блок коротких команд разработчика.
6. После решения разработчиков выполняет `confirm-decomposition`. Подтверждённый снимок сразу доступен аналитику, но разработка его ответа не ждёт.
7. Автоматически подготавливает квитанции реализации по точному составу карточек и сохраняет их в `returns/implementation-results/`.
8. Тестировщик берёт исходные срезы; обвязка подготавливает квитанцию по точному составу среза и сохраняет её в `returns/test-results/`.

## Независимые состояния

- Входная редакция управляет только актуальностью требований.
- Карточка хранит только состояние технической декомпозиции.
- Выполнение задачи фиксируется квитанцией реализации.
- Проверка фиксируется квитанцией среза.
- Фоновая передача аналитику не разрешает и не запрещает разработку.

```text
<package-id>/
├── README.md
├── handoff.json
├── .control/
└── revisions/
    ├── 001/
    │   ├── package/
    │   └── returns/
    │       ├── development-tasks/
    │       ├── decomposition-snapshots/
    │       ├── implementation-results/
    │       └── test-results/
    └── 001.zip
```

Текущий статус: `python .control/handoffctl.py status .`.
