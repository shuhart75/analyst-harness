# Пакет функциональности `<package-id>`, редакция `<revision>`

Этот пакет передаёт разработке требования по функциональности целиком. Он не содержит заранее утверждённой технической декомпозиции.

## Порядок работы

1. Прочитать `request.md`, `manifest.json` и приложенные требования со срезами.
2. Исследовать только необходимые контуры `coda`, их SDD, код и проверки.
3. Сформировать предложенные карточки будущих задач Jira в `returns/development-tasks/`.
4. Обсудить и изменить декомпозицию короткими командами из карточек.
5. После решения разработчиков выполнить `confirm-decomposition`. Команда создаёт неизменяемый снимок для аналитика и не блокирует начало разработки.
6. Реализовывать подтверждённые карточки по правилам разработческой SDD.
7. Регистрировать результат каждой карточки отдельно в `returns/implementation-results/`.
8. Тестировщики работают по исходным срезам и сохраняют результаты в `returns/test-results/`.

Оценка задачи и ключ Jira необязательны. Их отсутствие не мешает подтверждению декомпозиции, реализации или тестированию.

## Важные границы

- Декомпозиция определяется разработчиками по фактическим техническим границам.
- Подтверждение декомпозиции автоматически делает её доступной аналитику, но аналитик не согласовывает начало разработки.
- Карточка хранит состояние декомпозиции. Выполнение, передача аналитику и тестирование имеют отдельные состояния.
- Тестировщик получает тот же пакет, но основной единицей проверки остаётся срез, а карточки и квитанции реализации служат контекстом.
- Уже реализованное или реализованное иначе поведение фиксируется доказательствами и не останавливает независимую работу.
